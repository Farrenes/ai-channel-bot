# Универсальный контент-завод

## Общее описание

Этот документ описывает продукт BotTG как универсальный автоматизированный контент-завод для Telegram-каналов. Продукт не привязан к одной нише. Пользователь задает тему канала свободным текстом, настраивает источники и стиль, а система дальше автоматически собирает, фильтрует, скорит, генерирует, переписывает, проверяет и публикует посты по расписанию пользователя.

Основной рынок на старте — одиночные владельцы Telegram-каналов. Агентская и студийная модель тоже поддерживаются, но не являются главным источником денег на запуске.

## Позиционирование продукта

**Главное обещание:** автоматическое производство контента и автопостинг для Telegram-каналов, адаптированные под тему и стиль канала, с минимальным участием человека после начальной настройки.

**Основная аудитория:** одиночные владельцы Telegram-каналов.

**Вторичная аудитория:** агентства, редакторы медиа, операторы нескольких каналов.

**Главные ценностные столпы, по приоритету:**
- качество контента
- экономия времени
- рост аудитории как следствие качества

## Первый сценарий настройки

Система должна вести пользователя в таком порядке:

1. Ввести тему канала свободным текстом.
2. Дать системе распознать и нормализовать тему.
3. Настроить источники после того, как тема уже известна.
4. Настроить стиль после источников.
5. Настроить расписание публикаций.

### Ввод темы

Пользователь вводит тему канала свободным текстом. Система должна разбирать и нормализовать это описание, а не заставлять выбирать готовую категорию.

Примеры:
- "новости про мобильные приложения и стартапы"
- "политический канал с иронией"
- "крипта, рынок и мемы"

Нормализованная тема становится управляющим сигналом для:
- проверки релевантности источников
- фильтрации контента
- генерации промптов
- обнаружения ухода канала в сторону от темы

## Система источников

### Базовый каталог источников

В продукте должен быть базовый каталог источников, сгруппированный по основным тематикам каналов. Этот каталог не привязан к одной нише. Он должен развиваться в широкую, авторитетную, тематически размеченную библиотеку источников.

Первые семейства тем, которые уже определены:
- новости и агрегаторы
- политика
- юмор и мемы
- видеоигры
- криптовалюты
- софт и приложения
- экономика и финансы
- скидки и ритейл
- госуслуги и сервисы

Конкретный список источников по каждой теме можно расширять позже.

### Модель выбора источников

Пользователь должен видеть:
- рекомендованный список источников для распознанной темы
- короткое описание каждого источника
- причину, почему источник релевантен
- возможность добавить свой источник по URL

### Добавление пользовательского источника

Пользователь передает только URL. Система остальное определяет сама и записывает в базу.

Система должна автоматически определить:
- название источника
- описание источника
- соответствие теме
- тип источника
- оценку авторитетности
- режим доступа к контенту: RSS, API или HTML

### Проверка источника

Перед добавлением пользовательского источника система обязана проверить:
- доступность
- тип контента
- соответствие теме
- авторитетность

Если источник доступен, но выглядит слабым или сомнительным, система должна предупредить пользователя и попросить подтверждение перед добавлением.

### Метаданные источника в базе

У источника должны храниться:
- URL
- название
- описание
- тематика
- тип источника
- авторитетность
- статус проверки
- дата последней проверки
- режим доступа: RSS, API или HTML

## Ограничение нагрузки и fair use

Пользователь может добавлять много источников, но система не должна бездумно сканировать все источники постоянно.

Принцип работы:
- в интерфейсе источники не ограничены жестко
- в исполнении используется ограниченный активный пул
- новые источники сначала проходят проверку
- слабые или мусорные источники получают низкий приоритет
- плохие источники не расходуют crawl budget наравне с сильными

Рекомендуемое поведение на запуске:
- держать примерно 20-30 активных источников на канал в регулярной ротации
- использовать историю качества и релевантности для приоритизации повторных обходов
- ограничивать частоту повторных проверок слабых источников
- вводить лимит частоты обхода на источник и на домен

Это защищает:
- рост базы данных
- серверные ресурсы
- количество запросов
- стабильность парсеров

## Обучение стилю

Пользователь обучает систему через примеры постов и настройки стиля.

### Явные входы по стилю

На этапе настройки пользователь может указать:
- примеры постов
- ожидания по структуре
- желаемую длину
- тональность
- запретные темы, если нужно

### Стилевые признаки, которые система должна распознавать автоматически

Система должна обучаться распознавать:
- любимые форматы заголовков
- частоту эмодзи
- наличие списков и цитат
- фирменные слова и обороты
- общий стиль постов
- любимые темы

Цель — не только копировать поверхностные слова, а воспроизводить узнаваемую редакционную манеру канала.

## Стандарт качества контента

Для этого продукта качественный контент — это контент, который:
- интересен читателю
- совпадает со стилем канала
- полезен
- точен
- вовлекает
- хочется сохранить в избранное

Этот стандарт качества должен влиять на:
- приоритет источников
- scoring контента
- генерацию постов
- решения о переписывании
- долгосрочный рейтинг источников

## Безопасность и жесткие фильтры

Система обязана отбрасывать или сильно фильтровать контент, который:
- очевидно противоречит законам РФ в высокорисковых категориях
- содержит порнографию
- не соответствует заданной теме или стилю
- слишком длинный и плохо читаемый
- слишком сухой
- содержит очевидные нейромаркеры или нейроречевые клише

Универсальных тематических запретов нет, кроме:
- законов
- порнографии
- границ, заданных пользователем для своего канала

Поэтому слой модерации должен сочетать:
- универсальные правила безопасности
- пользовательские ограничения по стилю и теме

## Модель публикации

После настройки публикация должна быть автоматической.

В целевом состоянии владельцу или редактору не нужно подтверждать каждый пост. Участие человека ожидается главным образом на этапе начальной настройки и обучения системы стилю и источникам.

### Расписание

Пользователь сам задает расписание публикаций. Система публикует по этому расписанию, а не выбирает время публикации сама.

## Модель подписки

На старте подписки должны быть рассчитаны прежде всего на одиночных владельцев каналов, но с сохранением пути к агентской модели в будущем.

### Бета

Цена:
- 499 рублей в месяц

Задача:
- ранний доступ
- привлечение пользователей
- сбор кейсов

Лимиты на запуске:
- 1 канал
- до 3 постов в день
- расписание задает пользователь
- обучение стилю
- автоматическая проверка источников
- автоматический автопостинг

Эту цену нужно позиционировать как временную и не считать долгосрочной базовой экономикой.

### База

Цена:
- 990 рублей в месяц

Задача:
- основной массовый тариф

Предлагаемые лимиты:
- 1 канал
- до 5 постов в день
- более глубокая аналитика источников
- более высокий приоритет обработки
- лучшая история источников и постов

### Профи

Цена:
- 2490-3490 рублей в месяц

Задача:
- для активных владельцев каналов

Предлагаемые лимиты:
- 2 канала
- 5-7 постов в день на канал
- более глубокий анализ стиля
- расширенная аналитика
- более высокая пропускная способность проверки источников
- более высокий приоритет обработки

### Студия

Цена:
- от 7990 рублей в месяц

Задача:
- для агентств и многоканальных операций

Предлагаемые лимиты:
- несколько каналов
- отдельные настройки для каждого канала
- командный режим
- отчетность для агентств

## Предпосылки по экономике

Текущие допущения по цене:
- DeepSeek V4 Flash input: 13.56 рубля за 1М токенов
- DeepSeek V4 Flash output: 27.12 рубля за 1М токенов
- сервер: 4000 рублей в месяц

Тяжелый сценарий запуска для одного бета-пользователя:
- около 50 кандидатных материалов в день
- около 3 опубликованных постов в день
- около 5000 входных токенов на одного кандидата
- около 1 генерации + 3 переписываний + 2 проверок на один пост
- около 15000 выходных токенов на один финальный пост суммарно по всем проходам

Из этого следует, что тариф 499 рублей может быть хорош как акционный входной вариант, но слаб как постоянная основа экономики. Тариф 990 рублей выглядит более здоровой долгосрочной базой.

## Логика роста и SEO

Хотя продукт работает в Telegram, его контентный двигатель стоит проектировать с учетом поисковых сигналов и сигналов полезности.

Система должна со временем понимать:
- какие форматы заголовков работают лучше
- какие темы чаще сохраняют
- какие источники дают лучшие посты
- какие форматы проседают
- какие длины текста лучше подходят для каждого канала

По сути, продукт должен стать не просто генератором текста, а редакционным двигателем, который учится на результате.

Стратегическая формула продукта:

"Мы автоматизируем цикл контента канала: тема -> источники -> фильтрация -> scoring -> генерация -> проверка -> публикация -> обучение на результате."

## Рекомендация к запуску

Запускать продукт нужно как:
- универсальный
- автоматический
- понимающий стиль
- понимающий источники
- ориентированный на качество

Не стоит позиционировать его как узкого нишевого бота. Его нужно позиционировать как настраиваемый контент-завод для любой темы Telegram-канала, ограниченный качеством источников, обучением стилю и ресурсами исполнения.

## Открытые вопросы

Что стоит формализовать позже:
- точные семейства источников и их каталоги по темам
- точные лимиты активного пула источников по тарифам
- разовая ли тренировка стиля или постоянное дообучение
- доступны ли аналитика и отчеты всем тарифам или только части
- как именно реализуются проверки законов и качества: правилами, LLM или гибридом
